# Test guide – the prototype in 10 steps

What a human does to check the whole flow (Person A → Person B → Person C) on one page. Each step says what you should see.
Live mode needs the keys in `person_c/.env`; everything also works in **Demo mode** without network.

| # | Do this | Expected result |
|---|---------|-----------------|
| 1 | In a terminal: `cd` into the repo and run `./run_prototype.sh` | A `.venv` is created on first start, requirements install, the browser opens **http://localhost:8501**. The page shows the das schmeckt! logo, a 6-step stepper and the sidebar with four green "Live services" dots (LLM gateway, FLUX images, nutrition database, archive export). No Streamlit menu/footer. |
| 2 | Step 1 · click **Run Person A now** | A status box lists what runs (Google Trends, Wikimedia pageviews per topic, brand fit, archive, LLM pitch texts) and finishes in ~15–60 s. Left: the Google Trends rising-topics table with "in top 5" badges. Right: one row per pitch with a 14-day Wikipedia sparkline and the status (`available` / `no_article_found`). Caption: "5 proposals · N rejected · schema valid · measured X s". |
| 3 | Click **Next → Five proposals** | Five cards ranked #1–#5 with a **German recipe title** (not "Cookie (Food): …"), badges (Google interest, brand fit, repetition risk, archive status), "Why now", two concrete recipe ideas, the brand-fit reasoning, a table of **similar archive recipes with dates** (or "No comparable recipe found"), the content gap, risk bullets and the sparkline. The expander "Considered and rejected topics" lists every rejected topic with its reason. Each card has an "Evidence as supplied" expander with the compact JSON. |
| 4 | Step 3 · pick **#4 (Grünkohl)**, type the steering note `alltagstauglich, keine exotischen Zutaten`, click **Hand off to Person C** | The page jumps to step 4. In the sidebar the "Editor decision trail" shows "Proposals loaded (5)" and "You chose: Curly kale (Vegetable) · notes: …". Going back to step 3 shows the "Selected" card with the note and the expander `selection.json (Person C contract)` containing `picks`, `selected_ids`, `steering_notes`, `selected_by`, `timestamp`. |
| 5 | Step 4 · click **Generate the two recipes** | A status box shows every Person C stage as it happens (`[recipe] generated 2 recipes`, `[review] r1 v1 iteration 1: pass/revise`, `[image] r1: generated`, `[image] r1: verification score N/10`, `[nutrition] …`, `[render] cards written`). After 1.5–5 min two recipes appear side by side: FLUX photo, "image check N/10" badge, title, version, intro, servings/times, Zutaten, Zubereitung, Unser Tipp. |
| 6 | Step 4 · open **Send back to the Recipe Agent** under r1, type `weniger deftig, alltagstauglicher`, click **Send back and revise** | The status box shows the editor round (revise → review → nutrition → image → cards). r1 comes back as **version +1**, the expander now says "1 of 2 editor rounds left"; the decision trail is unchanged (Person C's own log records the editor comment). After two rounds the button is disabled. |
| 7 | Step 5 · look at both tabs | Per recipe: every **review round** as an expander (round, auto/editor, recipe version, PASS/REVISE, failing count) with a table of the **8 criteria + extras** (pass/fail badge, issues found, correction asked), "Corrections made → vN" after a revise round, the similar archive recipes compared, and "LLM reviewer used". Below: **Nutrition per serving** (quality badge, matched-ingredients badge, 9 metric tiles) and the ingredient table with database entry, grams, conversion, assumption flag, confidence, match type, kcal; closest-entry notes as captions. Then **Image verification** (score, retried?, foods not in recipe, missing components, prompt and attempts). |
| 8 | Step 6 · **Cards & impact** | Six measured tiles (Person A seconds, Person C seconds, review rounds, issues caught, corrections, pages per card = `1 / 1`), the seconds-per-stage table, the nutrition match-rate/image-score table. Tabs r1 / r2 / Both cards show the **A4 cards inline** with the yellow "KI-generierter Rezeptentwurf" label, the photo and the nutrition block. **Download HTML** saves the card; **Prepare PDF → Download PDF** appears when Playwright is installed, otherwise the print instructions. Open the HTML: it is one A4 page per recipe. |
| 9 | Sidebar · switch **Demo mode** on (or open `http://localhost:8501/?mode=demo`) | The pill changes to "DEMO · CACHED RUN", all six steps are ticked and show the committed run from `prototype/demo_cache/` (same screens, no network). Live buttons (Run Person A, Generate, Send back) are not offered. Switch Demo mode off → back to an empty live page. |
| 10 | Sidebar · **Replay a previous live run** (live mode) and **Save this run as the demo cache** | Every live run is listed by timestamp and reloads completely. Saving copies the run into `prototype/demo_cache/` with relative paths and no keys (the save refuses if a key-shaped string is found). Finally run the test suites: `python -m unittest discover -s tests` · `-s editor/tests -t .` · `-s person_c/tests` · `-s prototype/tests -t .` → all OK. |

If anything shows a red error box instead of a result, it is a friendly message (never a stack trace): read it, press **Dismiss**, and retry the step; the previous outputs stay.
